## 1부. ⚠️ 안정성·런타임 (Critical & High)

### 1. DataStore `runBlocking` 동기 접근 제거 🔴
- **위치**: `RemoteAutomationStore.kt` L30-125(약 10곳), `AndroidEncryptedGeminiApiKeyRepository.kt` L96-204, `AndroidEncryptedGrokAuthRepository.kt` L38-69, `AndroidAnalysisCustomDirectionRepository.kt` L36/56, `DataStoreAnimationScaleBackupStore.kt` L45-66, `DataStoreLastRunSnapshotRepository.kt` L53-61, `AndroidWildcardFolderRepository.kt` L72-104
- **문제**: 메인 스레드에서 호출되면 디스크를 읽는 동안 화면이 멈춥니다(ANR). `RemoteAutomationReceiverService` L57은 Main에서 호출.
- **개선**: `suspend`/`Flow`로 전환하거나 시작 시 캐시 선로딩.
- **효과**: 🚀 ANR·프레임 드랍 제거.

### 2. 자동화 시작 경로의 `runBlocking`
- `AndroidAutomationRuntime.kt#L58`의 `runBlocking { settingsStore.copyPromptOnStart.first() }` → 시작 전 suspend 읽기 또는 StateFlow 캐시.

### 3. Scoped Storage 우회 이중 경로 🔴
- **위치**: `AndroidWildcardFileRepository.kt` L335-355, L383-389, `AndroidEnvironmentGateway.kt` L24/36/78, `core/AppDefaults.kt` L11-15
- **문제**: `MANAGE_EXTERNAL_STORAGE` + `getExternalStorageDirectory()` + `"Documents/wildcard"` 하드코딩. SAF 저장소와 코드 경로가 둘로 갈라져 있습니다.
- **개선**: SAF(`OpenDocumentTree`) + persisted URI 하나로 단일화. 대량 목록은 `DocumentsContract` 쿼리.
- **효과**: 이중 경로 제거, OS 정책 부합. ⚠️ 큰 변경이므로 사용자 승인 후 단계 진행.

### 4. 비원자적 파일 저장 🟠
- `writeText`로 직접 덮어쓰면 중단 시 파일이 잘립니다 → tmp 작성 후 rename(`AtomicFile`).

### 5. 동기 파일 I/O 호출 스레드 🟠
- `readText`/`writeText` 호출부가 `Dispatchers.IO`인지 확인, 아니면 `withContext(io)`.

### 6. 쿠키 평문 저장 🟠
- `GeminiAccountCookieVault`가 쿠키 JSON을 SharedPreferences에 저장 → Keystore 암호화 검토.

## 2부. ⚡ 반응성·플랫폼 현대화

### 7. 고정 delay → 이벤트/조건 폴링 🟠
- `AccessibilityPromptAutomation.kt` L151/224/235/252/279/307/328/345. L190의 폴링 방식을 표준으로 확산, `TYPE_WINDOW_STATE_CHANGED` 이벤트 대기 병용.
- **효과**: 빠른 기기는 더 빠르게, 느린 기기는 덜 실패.

### 8. Dex 최근앱 좌표 탭 🟠
- `GLOBAL_ACTION_RECENTS` 우선, 좌표(132dp)는 폴백. 700ms 대기 → 이벤트 대기.

### 9. IME 강제 변경 🟠
- `softKeyboardController.showMode = SHOW_MODE_HIDDEN`으로 대체 가능한지 검토 → 서드파티 IME ID 3개·`adb pm grant` 안내 제거 가능.

### 10. 외부 앱 view-ID 산재 🟠
- `com.google.android.googlequicksearchbox:id/...` 약 30개를 `ExternalAppNodeIds.kt` 한 곳으로. 키보드 판별은 `AccessibilityWindowInfo.TYPE_INPUT_METHOD`. (`update-accessibility-nodes` 스킬과 연계)
- 참고: force-stop 설정앱 자동화(`GoogleAppForceStopAutomation.kt`)는 대안이 제한적이라 유지 가능.

### 11. 재시도 폭풍 방어 🟠
- Grok 폴링: 연속 실패 시 지수 백오프+N회 중단. Gemini 재시도: 최대 횟수·지터·429/5xx 구분. (⚠️ 현재 코드 정독 필요)

### 12. 하드코딩 색상 → 팔레트 토큰 🟠
- `AnalysisScreen.kt` L250/L1436-1437, `StatusSettingsDialog.kt` L54, `AppMultilineTextField.kt` L281-282 → `AppThemePalette`에 warning/danger/highlight 추가. (`PromptEditorActions.kt` 브랜드색은 의도적일 수 있어 낮은 우선순위) `docs/디자인.md` 기준 준수.

### 13. LazyColumn key 🟠
- `"$index|$line"` key는 편집 시 상태가 초기화됩니다 → 줄별 안정 id. `PromptSnippetDialog.kt` L579 `items`의 key도 확인.

### 14~16. 🟡 소소한 항목
- 14: `collectAsState()` → `collectAsStateWithLifecycle`(FloatingOverlayBar는 의도적일 수 있음), `delay(30_000)` 루프(`GeminiUsageSummaryButton.kt` L80, `MultiGeminiUsageDialog.kt` L237)에 lifecycle 적용, Service `onDestroy`의 scope cancel 확인.
- 15: `height(30.dp)` → `heightIn(min)`+`minimumInteractiveComponentSize`, 9.sp 등 typography 토큰.
- 16: 액션 문자열 `"${packageName}.remote.STOP_RECEIVER"`.
