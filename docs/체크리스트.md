### 1. 3개 탭 상태 결합(`remember`)으로 인한 숨겨진 탭 강제 다시 그리기 해소
- **관련 파일**:
  - 3탭 조립 화면: [`AutomationApp.kt`](file:///c:/Users/joajo/AndroidStudioProjects/gemgemgen/app/src/main/java/com/example/gemgemgen/ui/AutomationApp.kt#L323-L359)
  - 탭 전환 컨테이너: [`MainTabbedScreen.kt`](file:///c:/Users/joajo/AndroidStudioProjects/gemgemgen/app/src/main/java/com/example/gemgemgen/ui/MainTabbedScreen.kt#L105-L108), [`MainTabbedScreen.kt` 탭 본문 렌더링](file:///c:/Users/joajo/AndroidStudioProjects/gemgemgen/app/src/main/java/com/example/gemgemgen/ui/MainTabbedScreen.kt#L231-L250)
- **어떤 문제인가요?**:
  - [`MainTabbedScreen.kt`](file:///c:/Users/joajo/AndroidStudioProjects/gemgemgen/app/src/main/java/com/example/gemgemgen/ui/MainTabbedScreen.kt#L231-L250)는 탭 전환 시 깜빡임을 막기 위해 한 번 방문한 모든 탭을 화면 뒤에 투명하게(`alpha = 0f`) 상주시켜 둡니다.
  - 그런데 [`AutomationApp.kt`](file:///c:/Users/joajo/AndroidStudioProjects/gemgemgen/app/src/main/java/com/example/gemgemgen/ui/AutomationApp.kt#L323-L359)에서 `val tabs = remember(mainUiState, automationBarUiState, promptTemplateState, analysisUiState, analysisPromptState, wildcardUiState, ...)`처럼 **3개 탭의 모든 상태를 하나의 `remember` 열쇠로 묶어** `List<MainTabPage>`와 각 탭의 `content` 람다를 매번 새로 만들고 있습니다.
- **실제 영향**:
  - 자동화 탭에서 프롬프트를 한 글자 입력하거나 자동화 대기 타이머가 1초씩 바뀔 때마다, **화면에 보이지도 않는 분석 탭(`AnalysisScreen`)과 와일드카드 탭(`WildcardScreen`)의 UI 함수까지 매번 강제로 다시 실행(Recomposition)**되어 타이핑과 화면 반응이 무거워집니다.
- **개선 방안**:
  - 각 탭의 `MainTabPage`(또는 탭별 컴포저블 래퍼)가 **자기 탭에 해당하는 상태만 읽도록 분리**하여, 자동화 탭의 상태가 변할 때 분석 탭·와일드카드 탭은 리컴포지션을 건너뛰게(Skip) 만듭니다.

### 2. 와일드카드 편집 화면의 매 프레임 전체 줄 재분할(`get()`) 캐싱
- **관련 파일**:
  - 와일드카드 UI 모델: [`WildcardUiModels.kt`](file:///c:/Users/joajo/AndroidStudioProjects/gemgemgen/app/src/main/java/com/example/gemgemgen/wildcard/ui/WildcardUiModels.kt#L58-L79)
- **어떤 문제인가요?**:
  - `WildcardUiState` 내부의 `selectableLines`(`get() = WildcardDynamicPromptComposer.selectableLines(editingText)`)와 `fileItems`(`get() = files.map { ... }`)가 값을 보관하지 않고 **읽을 때마다 매번 계산하는 프로퍼티(`get()`)**로 선언되어 있습니다.
  - `selectableLines`는 `canRequestClassify`(59행), `canSelectAllLines`(61행), 그리고 [`WildcardScreen.kt`](file:///c:/Users/joajo/AndroidStudioProjects/gemgemgen/app/src/main/java/com/example/gemgemgen/wildcard/ui/WildcardScreen.kt)의 줄 목록 렌더링 과정에서 **한 화면을 그리는 동안에도 여러 번 반복 호출**됩니다.
- **실제 영향**:
  - 와일드카드 파일이 길수록 화면이 조금만 갱신되어도 전체 텍스트를 줄 단위로 쪼개고(`lines()`), 공백을 다듬고(`trim()`), 새 리스트를 만드는 작업이 매 프레임 수차례 반복되어 스크롤·줄 선택 반응성을 떨어뜨립니다.
- **개선 방안**:
  - `selectableLines`와 `fileItems`를 `get()` 대신 `WildcardUiState` 인스턴스 생성 시 1회만 계산되어 저장되는 일반 프로퍼티(또는 `editingText`/`files` 변경 시에만 갱신되는 필드)로 변경합니다.

  - 자동화 시작 진입점: [`AutomationViewModel.kt`](file:///c:/Users/joajo/AndroidStudioProjects/gemgemgen/app/src/main/java/com/example/gemgemgen/automation/ui/AutomationViewModel.kt#L774-L815)
  - 이력 및 클립보드 기록 유스케이스: [`RecordAutomationHistoryUseCase.kt`](file:///c:/Users/joajo/AndroidStudioProjects/gemgemgen/app/src/main/java/com/example/gemgemgen/automation/usecase/RecordAutomationHistoryUseCase.kt#L24-L36)
  - 이력 저장소 래퍼: [`PromptHistoryStore.kt`](file:///c:/Users/joajo/AndroidStudioProjects/gemgemgen/app/src/main/java/com/example/gemgemgen/automation/usecase/PromptHistoryStore.kt#L29-L51)
  - SharedPreferences JSON 파서: [`SharedPreferencesPromptHistoryRepository.kt`](file:///c:/Users/joajo/AndroidStudioProjects/gemgemgen/app/src/main/java/com/example/gemgemgen/automation/android/SharedPreferencesPromptHistoryRepository.kt#L18-L36)
- **어떤 문제인가요?**:
  - 사용자가 '시작' 버튼을 누르면 [`AutomationViewModel.runAutomation()`](file:///c:/Users/joajo/AndroidStudioProjects/gemgemgen/app/src/main/java/com/example/gemgemgen/automation/ui/AutomationViewModel.kt#L787-L788)이 백그라운드 코루틴으로 들어가기 전에 **화면(메인 UI) 스레드에서 직접 `promptHistoryStore?.load()`를 호출**해 SharedPreferences의 이력 JSON 전체를 동기 파싱합니다.
  - 게다가 이때 `promptEditor.onAutomationStarted(...)`에 전달되는 이력은 **방금 실행한 새 프롬프트가 추가되기 전의 옛날 이력**이며, 정작 코루틴 안쪽의 [`RecordAutomationHistoryUseCase.record()`](file:///c:/Users/joajo/AndroidStudioProjects/gemgemgen/app/src/main/java/com/example/gemgemgen/automation/usecase/RecordAutomationHistoryUseCase.kt#L24-L36)에서 똑같은 JSON을 **한 번 더 파싱하고 전체 재직렬화하여 저장**합니다.
  - 또한 `RecordAutomationHistoryUseCase.record()` 마지막 줄(35행)에서 **매 실행마다 무조건 시스템 클립보드에 프롬프트 전체를 강제로 덮어씁니다(`clipboardGateway.writeText(prompt)`)**. (접근성 입력 시에는 `ACTION_SET_TEXT`를 직접 쓰고 있어 클립보드 붙여넣기를 쓰지 않는데도 매번 사용자 클립보드를 덮어쓰고 시스템 클립보드 토스트/IPC를 유발합니다.)
- **실제 영향**:
  - 시작 버튼을 누르는 순간 메인 스레드에서 JSON 파싱이 돌아 버튼 반응이 미세하게 멈칫하고, 동일 이력 JSON을 2번 연속 읽으며, 사용자의 개인 클립보드 내용이 자동화 시작 때마다 강제로 지워집니다.
- **개선 방안**:
  - `PromptHistoryStore`에 인메모리 캐시를 두거나 이력 로드·갱신을 단일 흐름으로 합쳐 **메인 스레드 중복 JSON 파싱을 제거**하고 최신 이력이 `promptEditor`에 즉시 반영되게 합니다.
  - `RecordAutomationHistoryUseCase`에서 매번 수행하던 불필요한 클립보드 강제 복사(`clipboardGateway.writeText`)를 제거합니다.
