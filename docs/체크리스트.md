### 1. `GeminiAccessibilityService.closeAppFromRecents` 코루틴 취소 시 재귀 클릭 고스트 작업 잔류
- **관련 파일**: [`GeminiAccessibilityService.kt` (L275-L318, L374-L424)](file:///c:/Users/joajo/AndroidStudioProjects/gemgemgen/app/src/main/java/com/example/gemgemgen/automation/android/GeminiAccessibilityService.kt#L275-L318)
- **어떤 문제인가요?**:
  - 📱 **사용자가 겪는 불편 (UX)**: 자동화를 중간에 중지했는데도 스마트폰이 혼자 최근 앱 카드를 마구 닫더니, 내가 보고 있던 메신저나 브라우저 창까지 강제로 꺼버립니다.
  - **기술적 원인**: 자동화 중지 시 continuation 콜백만 null로 만들고 `closeNextTaskCard` 재귀 루프를 취소하지 않아, 백그라운드에서 최대 10번 동안 최근 앱 카드를 닫고 마지막에 백 버튼을 날려 사용자의 다른 앱을 강제로 꺼버립니다.
- **현대화 개선 방안**:
  - `activeCloseTaskJob?.cancel()`을 명시적으로 연결하여 중지 즉시 루프를 강제 종료합니다.
- **기대 효과**:
  - 🚀 작업 취소 시 타 앱 화면 간섭 부작용 100% 방지.

### 3. Flow 앱 자동화의 하드코딩 매직 좌표 터치 우회 (`437f, 1315f`)
- **관련 파일**: [`FlowPromptAutomation.kt` (L68-L75, L152-L165)](file:///c:/Users/joajo/AndroidStudioProjects/gemgemgen/app/src/main/java/com/example/gemgemgen/automation/android/FlowPromptAutomation.kt#L68-L75)
- **어떤 문제인가요?**:
  - 📱 **사용자가 겪는 불편 (UX)**: 태블릿이나 가로 화면에서 Flow 앱을 실행하면 입력창이 아니라 엉뚱한 허공이나 다른 버튼을 터치하여 텍스트가 입력되지 않습니다.
  - **기술적 원인**: 표준 노드 클릭(`ACTION_CLICK`)이 가능함에도 `dispatchGesture`를 1순위로 호출하며, bounds 획득 실패 시 `437f, 1315f`라는 특정 폰 세로 모드 전용 절대 좌표를 터치합니다.
- **현대화 개선 방안**:
  - 1순위로 네이티브 노드 액션(`ACTION_CLICK`, `ACTION_FOCUS`)을 실행하고, 제스처 주입은 실제 뷰 바운드가 있을 때만 동적 중심점 좌표로 격하(Fallback)합니다.
- **기대 효과**:
  - 🚀 대화면/태블릿/가로모드 오터치 원천 방지.
