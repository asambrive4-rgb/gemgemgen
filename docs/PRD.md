# PRD: Gemini Prompt Auto Sender for Android/Kotlin

- 문서 버전: v0.2 Draft
- 작성일: 2026-06-07
- 제품 형태: 개인용 Android/Kotlin 자동화 앱
- 대상 앱: Google Gemini Android 앱
- 핵심 목표: 기존 Tasker + AutoInput 자동화 구현을 Android/Kotlin 네이티브 앱으로 재현

---

## 1. 제품 개요

### 1.1 제품 한 줄 설명

사용자가 준비한 프롬프트 템플릿과 `Download/wildcard/*.txt` 파일을 기반으로, 앱이 Gemini 앱을 직접 열고 각 프롬프트를 새 채팅 세션에 자동 전송하는 개인용 Android 자동화 앱.

### 1.2 제품의 본질

이 제품은 AI API 클라이언트가 아니다.  
Gemini API를 사용하지 않고, Android 기기 위에서 **Gemini 앱 UI를 자동 조작**한다.

기존 Tasker 구현의 핵심 동작은 다음과 같다.

1. 클립보드에서 원본 프롬프트 템플릿을 가져온다.
2. `Download/wildcard/*.txt` 파일을 읽는다.
3. 템플릿 안의 와일드카드 토큰을 랜덤 치환한다.
4. Gemini 앱을 연다.
5. 새 채팅을 연다.
6. 입력창에 프롬프트를 붙여넣거나 입력한다.
7. 보내기 버튼을 누른다.
8. 기본 10회 반복한다.
9. 각 프롬프트는 각각 독립된 새 채팅 세션에 전송한다.

### 1.3 MVP 관점

MVP의 목적은 새로운 프롬프트 관리 앱을 만드는 것이 아니라, 기존 Tasker 자동화의 동작을 Kotlin 앱으로 최대한 동일하게 재현하는 것이다.

따라서 MVP의 우선순위는 다음과 같다.

1. Gemini 앱 자동 실행
2. Gemini 새 채팅 생성
3. 세션 시작 마커 전송
4. 와일드카드 txt 로드
5. 토큰 랜덤 치환
6. 기본 10회 반복 전송
7. 각 프롬프트마다 새 채팅 생성
8. 입력기 전환 및 복구
9. 실행 로그와 중지 기능

와일드카드 편집 UI, 프롬프트 미리보기 고도화, 다중 AI 앱 지원은 후순위다.

### 1.4 구현 판단과 MVP 원칙

현재 목표가 Gemini API 연동이 아니라 Gemini Android 앱 UI 자동 조작이므로, Android/Kotlin 네이티브 앱과 AccessibilityService 기반 구현은 MVP에 적합하다.

다만 UI 자동 조작은 Gemini 앱 화면 변경에 취약하므로, MVP의 품질 기준은 화면 기능의 수보다 다음 항목에 둔다.

1. 단계별 상태가 명확한 실행 흐름
2. 실패 지점을 알 수 있는 최소 로그
3. 실패, 완료, 중지 시 입력기 복구
4. 지나치게 무겁지 않은 앱 구조

MVP에서는 다음 방향을 따른다.

- `Room`, `Hilt`, 복잡한 클린 아키텍처, 다중 앱 추상화는 도입하지 않는다.
- 설정은 `DataStore` 또는 `SharedPreferences` 수준으로 가볍게 저장한다.
- 로그는 앱 내부의 간단한 저장 방식으로 시작한다.
- 좌표 기반 fallback은 당장 MVP에 포함하지 않고, selector 기반 탐지가 충분하지 않을 때를 위한 후순위 보험으로 남긴다.
- Null Keyboard는 이미 설치되어 있다고 전제한다.
- Gemini UI 탐지는 한국어 Gemini 앱 UI를 기준으로 한다.
- MVP의 기본 입력 방식은 클립보드 paste가 아니라 접근성 `ACTION_SET_TEXT` 직접 입력으로 한다.
- 반복 전송 중에는 `Download/wildcard` 파일을 매번 다시 읽지 않고, 실행 시작 시 1회 로드한 후보 목록을 사용한다.

## 2. 배경과 문제 정의

### 2.1 현재 사용 방식

현재 사용자는 Tasker + AutoInput 기반 자동화를 통해 Gemini 앱에 프롬프트를 반복 전송하고 있다.

현재 자동화는 다음 요소에 의존한다.

- Tasker 태스크
- AutoInput 플러그인
- Android 접근성 제어
- 클립보드
- Null Keyboard
- `WRITE_SECURE_SETTINGS` 권한
- Gemini 앱 UI 텍스트와 리소스 ID
- `Download/wildcard/*.txt` 후보 파일
- JavaScriptlet 기반 랜덤 치환 로직

### 2.2 현재 방식의 문제

| 문제 | 설명 |
|---|---|
| 유지보수 난이도 | Tasker XML과 JavaScriptlet을 직접 수정해야 한다. |
| 실행 상태 가시성 부족 | 현재 몇 번째 프롬프트가 전송 중인지 명확히 보기 어렵다. |
| 실패 복구 취약 | 중간 실패 시 입력기나 클립보드가 원래 상태로 복구되지 않을 수 있다. |
| 기기 의존성 | Samsung Keyboard, Gemini 앱 UI ID, 한국어 버튼 텍스트 등에 의존한다. |
| 설정 분산 | 프롬프트 템플릿, txt 파일, Tasker 설정, 권한 설정이 분리되어 있다. |
| 중지 UX 부족 | 실행 중 사용자가 안전하게 중지하기 어렵다. |

### 2.3 해결하고자 하는 문제

MVP는 다음 문제를 해결한다.

- Tasker 구현을 Android/Kotlin 앱으로 이동한다.
- 실행 흐름을 앱 안에서 명확하게 제어한다.
- 접근성 서비스와 입력기 전환을 앱 단위로 관리한다.
- 실패 시 로그를 남기고 복구를 시도한다.
- 반복 횟수를 기본값 10회에서 사용자가 변경할 수 있게 한다.

## 3. 목표와 비목표

### 3.1 목표

#### G1. 기존 Tasker 자동화의 핵심 동작 재현

앱은 기존 Tasker 태스크와 동일하게 Gemini 앱에 프롬프트를 자동 전송해야 한다.

#### G2. 각 프롬프트를 독립 채팅으로 전송

자동 생성된 각 프롬프트는 매번 Gemini의 새 채팅 세션에 전송되어야 한다.

#### G3. 세션 시작 마커 전송

자동화 실행 시작 시, 별도 새 채팅에 세션 시작 마커를 먼저 전송해야 한다.

기본 마커 문구:

```text
자연수의 가장 첫 번째 숫자는? 숫자 하나로만 답변해.
```

이 마커는 Gemini가 일관적으로 `1`을 답변하도록 유도하여, Gemini 채팅 목록에서 이번 실행 세션의 시작점을 쉽게 찾기 위한 용도다.

#### G4. txt 기반 와일드카드 워크플로우 유지

기존 `Download/wildcard/*.txt` 파일 기반 워크플로우를 유지한다.

#### G5. 자동화 안정성 강화

앱은 실행 중 상태를 보여주고, 실패 시 가능한 복구를 수행해야 한다.

### 3.2 비목표

MVP에서 다음은 목표가 아니다.

- Gemini API 연동
- ChatGPT, Claude 등 다른 앱 지원
- 상용 배포용 온보딩
- 고급 프롬프트 라이브러리
- 클라우드 동기화
- 다중 디바이스 지원
- 완성도 높은 와일드카드 편집 UX
- 이미지 생성 결과 수집 또는 다운로드

## 4. 사용자와 사용 환경

### 4.1 타깃 사용자

| 항목 | 내용 |
|---|---|
| 사용자 유형 | 본인만 사용하는 개인 자동화 사용자 |
| 기술 수준 | Android 자동화, Tasker, ADB 사용에 익숙함 |
| 주요 목적 | Gemini에 이미지 프롬프트 변형을 빠르게 대량 전송 |
| 상용 배포 고려 | 없음 또는 후순위 |

### 4.2 사용 환경

- Android 기기
- Kotlin 기반 네이티브 앱
- Gemini 앱 설치 필요
- Gemini 앱 UI 언어는 한국어 기준
- 접근성 서비스 활성화 필요
- ADB를 통한 `WRITE_SECURE_SETTINGS` 권한 부여 허용
- Null Keyboard 설치 전제
- 기존 와일드카드 txt 파일 사용

### 4.3 권한 전제

개인용 앱이므로 ADB를 통한 권한 부여를 허용한다.

```bash
adb shell pm grant <package_name> android.permission.WRITE_SECURE_SETTINGS
```

이 권한은 다음 목적으로 사용한다.

- 현재 기본 입력기 저장
- 설치되어 있는 Null Keyboard 또는 지정 입력기로 전환
- 자동화 종료 후 원래 입력기로 복구
- Gemini 자동 입력 중 키보드가 UI를 가리는 문제 최소화

Null Keyboard는 MVP에서 앱이 설치하거나 동봉하지 않는다. 이미 설치되어 있는 환경을 전제로 하되, 앱은 활성 입력기 목록 감지를 필수 조건으로 삼지 않고 Tasker 원본 ID로 전환을 시도한 뒤 결과를 확인한다.

## 5. 핵심 사용자 시나리오

### 5.1 기본 시나리오: 프롬프트 10개 자동 전송

#### 전제

- 사용자는 Gemini 앱을 설치해두었다.
- 앱 접근성 서비스가 활성화되어 있다.
- `WRITE_SECURE_SETTINGS` 권한이 ADB로 부여되어 있다.
- 사용자는 `Download/wildcard/` 폴더에 txt 파일을 준비해두었다.
- 사용자는 원본 프롬프트 템플릿을 클립보드에 복사했거나 앱에 입력했다.

#### 흐름

1. 사용자가 앱을 연다.
2. 앱이 권한과 환경 상태를 확인한다.
3. 앱이 원본 프롬프트를 불러온다.
4. 앱이 와일드카드 txt 파일을 로드한다.
5. 사용자가 반복 횟수 10회를 확인한다.
6. 사용자가 실행 버튼을 누른다.
7. 앱이 현재 입력기를 저장한다.
8. 앱이 입력기를 Null Keyboard로 전환한다.
9. 앱이 Gemini 앱을 실행한다.
10. 앱이 새 채팅을 연다.
11. 앱이 세션 시작 마커를 전송한다.
12. 앱이 첫 번째 랜덤 프롬프트를 생성한다.
13. 앱이 Gemini에서 새 채팅을 연다.
14. 앱이 접근성 `ACTION_SET_TEXT`로 프롬프트를 입력창에 직접 입력한다.
15. 앱이 보내기 버튼이 활성화될 때까지 기다린 뒤 누른다.
16. 12~15번을 설정된 횟수만큼 반복한다.
17. 앱이 원래 입력기를 복구한다.
18. 앱이 실행 결과 로그를 보여준다.

#### 기대 결과

기본 반복 횟수 10회 기준:

- 세션 시작 마커 채팅 1개 생성
- 랜덤 프롬프트 채팅 10개 생성
- 총 11개 Gemini 채팅 세션 생성

## 6. 핵심 UX 플로우

### 6.1 전체 실행 플로우

```text
앱 실행
→ 환경 상태 확인
→ 프롬프트 템플릿 확보
→ 와일드카드 txt 1회 로드
→ 실행 옵션 확인
→ 실행 시작
→ 현재 입력기 저장
→ Null Keyboard 전환
→ Gemini 앱 실행
→ 새 채팅 열기
→ 세션 시작 마커 전송
→ 반복 루프 시작
    → 로드된 후보 목록으로 랜덤 프롬프트 1개 생성
    → 새 채팅 열기
    → 입력창 찾기
    → ACTION_SET_TEXT로 프롬프트 직접 입력
    → 보내기 버튼 활성화 대기
    → 보내기 클릭 및 전송 확인
    → 결과 로그 기록
→ 반복 루프 종료
→ 입력기 복구
→ 실행 요약 표시
```

### 6.2 반복 루프 상세

```text
for i in 1..repeatCount:
    basePrompt 복사
    basePrompt 안의 토큰 탐지
    실행 시작 시 1회 로드한 후보 목록에서 각 토큰에 대응하는 후보 확인
    각 토큰마다 후보 1개 랜덤 선택
    최종 프롬프트 생성
    Gemini 새 채팅 열기
    입력창 활성화
    최종 프롬프트를 ACTION_SET_TEXT로 직접 입력
    보내기 버튼 활성화 대기
    보내기 버튼 클릭 및 전송 확인
    i번째 전송 성공/실패 로그 기록
```

### 6.3 세션 마커 정책

| 항목 | 정책 |
|---|---|
| 실행 시점 | 반복 루프 시작 전 |
| 채팅 세션 | 별도 새 채팅 1개 |
| 기본 문구 | `자연수의 가장 첫 번째 숫자는? 숫자 하나로만 답변해.` |
| 기대 응답 | `1` |
| 목적 | Gemini 채팅 목록에서 이번 자동화 세션의 시작점 식별 |
| MVP 수정 가능 여부 | 기본값 고정, 설정 변경은 후순위 |

### 6.4 실행 상태 머신

자동화는 단순 반복문이 아니라 명확한 상태 전이로 구현한다.

기본 상태:

```text
READY
CHECKING_ENVIRONMENT
SAVING_ORIGINAL_STATE
SWITCHING_IME
OPENING_GEMINI
OPENING_MARKER_CHAT
SENDING_MARKER
GENERATING_PROMPT
OPENING_PROMPT_CHAT
FOCUSING_INPUT
ENTERING_PROMPT
TAPPING_SEND
RESTORING_STATE
COMPLETED
FAILED
CANCELLED
```

각 상태는 다음 정보를 갱신해야 한다.

- 현재 단계
- 현재 반복 번호
- 전체 반복 횟수
- 마지막 생성 프롬프트
- 마지막 성공/실패 상태

### 6.5 재시도와 복구 원칙

MVP는 자동화 성공률을 높이기 위해 단계별 wait/retry를 둔다. 정확한 대기 시간은 개발 중 조정하되, 모든 재시도는 로그와 상태 화면에서 현재 단계를 알 수 있어야 한다.

권장 초안:

| 단계 | 재시도 정책 |
|---|---|
| Gemini 앱 실행 | 실행 후 패키지 전환 확인 |
| 새 채팅 탐지 | 최대 3회 재시도 |
| 입력창 탐지 | 최대 5회 재시도 |
| 프롬프트 입력 | `ACTION_SET_TEXT` 직접 입력 후 입력창 반영 확인 |
| 보내기 버튼 탐지 | 버튼 활성화와 전송 완료 확인까지 재시도 |

오류 또는 중지 시에는 다음 순서로 복구한다.

1. 자동화 루프 중단
2. 입력기 복구 시도
3. 로그 저장
4. 사용자에게 실패 또는 중지 지점 표시

## 7. 기능 요구사항

## 7.1 앱 시작 및 상태 점검

### FR-001. 환경 상태 점검

앱은 메인 화면에서 다음 상태를 확인하고 표시해야 한다.

| 상태 | 필수 여부 | 설명 |
|---|---:|---|
| Gemini 앱 설치 여부 | 필수 | 대상 앱 실행 가능 여부 |
| 접근성 서비스 활성화 여부 | 필수 | Gemini UI 자동 조작 가능 여부 |
| `WRITE_SECURE_SETTINGS` 권한 여부 | 필수 | 입력기 전환 가능 여부 |
| 와일드카드 폴더 접근 가능 여부 | 필수 | txt 파일 로드 가능 여부 |
| 원본 프롬프트 존재 여부 | 필수 | 자동 전송할 템플릿 존재 여부 |

### FR-002. 상태별 액션 제공

상태가 충족되지 않았을 때 앱은 사용자가 다음 조치를 할 수 있도록 안내해야 한다.

| 상태 | 액션 |
|---|---|
| Gemini 앱 없음 | 설치 필요 안내 또는 패키지명 확인 안내 |
| 접근성 서비스 꺼짐 | 접근성 설정 화면으로 이동 |
| 권한 없음 | ADB 명령어 표시 |
| 와일드카드 폴더 없음 | 폴더 생성 안내 |
| 프롬프트 없음 | 클립보드 가져오기 또는 직접 입력 안내 |

## 7.2 프롬프트 템플릿 입력

### FR-010. 클립보드에서 프롬프트 가져오기

앱은 사용자가 클립보드의 텍스트를 원본 프롬프트로 가져올 수 있어야 한다.

### FR-011. 앱 내부 입력창 제공

앱은 원본 프롬프트를 직접 붙여넣거나 수정할 수 있는 텍스트 입력창을 제공해야 한다.

### FR-012. 원본 프롬프트 보존

자동화 실행 전 원본 프롬프트를 앱 상태로 보존해야 한다. 클립보드에서 가져오기 버튼은 사용자의 현재 클립보드 텍스트를 읽어 앱 입력창에 채우는 기능일 뿐이며, MVP 전송 흐름은 클립보드를 수정하지 않는다.

## 7.3 와일드카드 txt 로드

### FR-020. 기본 와일드카드 경로

앱은 기본적으로 다음 경로에서 txt 파일을 읽는다.

```text
Download/wildcard/
```

### FR-021. 파일명 기반 자동 토큰 매핑

앱은 `Download/wildcard/` 경로 안의 모든 txt 파일을 별도 설정 없이 와일드카드 후보 파일로 사용한다.

토큰 이름은 txt 파일의 확장자를 제외한 파일명으로 만든다.

예:

| 파일명 | 토큰 |
|---|---|
| `all.txt` | `__all__` |
| `hair.txt` | `__hair__` |
| `예시.txt` | `__예시__` |

특정 파일명을 코드에 하드코딩하지 않는다.

### FR-022. 파일 포맷

각 txt 파일은 다음 규칙을 따른다.

- 한 줄에 후보 하나
- 빈 줄은 무시
- 앞뒤 공백은 trim 처리
- 파일 인코딩은 UTF-8 권장

예시:

```text
short black hair
long blonde hair
brown bob cut
silver twin tails
```

### FR-023. 토큰이 없는 파일 처리

프롬프트에 특정 토큰이 없으면 해당 파일이 없어도 실행을 막지 않는다.

예:

- 프롬프트에 `__hair__`가 없으면 `hair.txt`가 없어도 오류가 아니다.

### FR-024. 토큰 또는 후보가 없어도 실행 허용

프롬프트에 와일드카드 토큰이 하나도 없어도 오류로 처리하지 않는다.

이 경우 앱은 원본 프롬프트를 반복 횟수만큼 그대로 생성하고 전송한다.

프롬프트에 포함된 토큰에 대응하는 파일이 없거나 후보가 0개인 경우에도 실행을 막지 않는다.
해당 토큰은 치환하지 않고 원문 그대로 둔다.

## 7.4 랜덤 치환

### FR-030. 반복마다 새 랜덤 치환

앱은 매 반복마다 원본 프롬프트에서 새로 랜덤 치환을 수행해야 한다.

와일드카드 txt 파일은 실행 시작 시 1회 로드하고, 반복 중에는 이미 로드된 후보 목록에서 랜덤 선택만 수행한다. 저사양 기기에서 파일 I/O와 상태 관리를 줄이기 위해 10개 프롬프트를 한 번에 모두 확정하지 않고, 각 전송 직전에 1개씩 생성한다.

### FR-031. 토큰 전체 치환

같은 토큰이 프롬프트 내 여러 번 등장하면 모두 같은 선택값으로 치환한다.

예:

```text
__color__ dress with __color__ ribbon
```

`__color__ = red`가 선택되면:

```text
red dress with red ribbon
```

### FR-032. 랜덤 소스

MVP에서는 Kotlin의 보안 랜덤 또는 시스템 랜덤 기반 구현을 사용한다.

권장 구현:

- `SecureRandom`
- 각 토큰마다 후보 목록에서 균등 랜덤 선택

### FR-033. 디버그 정보 기록 제외

MVP에서는 반복별 치환 상세 정보 같은 디버그 로그를 저장하지 않는다.

개인용 앱이며 가벼운 실행이 중요한 목표이므로, 로그는 실행 결과 확인과 오류 파악에 필요한 최소 정보만 남긴다.

## 7.5 Gemini 앱 자동 조작

### FR-040. Gemini 앱 실행

앱은 Gemini Android 앱을 실행해야 한다.

기본 패키지명:

```text
com.google.android.apps.bard
```

### FR-041. 새 채팅 열기

앱은 Gemini에서 새 채팅을 열 수 있어야 한다.

우선 탐지 전략:

1. 접근성 노드 텍스트 또는 contentDescription 기반: `사이드바 열기`
2. 접근성 노드 텍스트 기반: `채팅 검색`과 가장 가까운 `새 채팅`
3. 리소스 ID 기반 탐지

Gemini 화면 안에 `새 채팅` 후보가 여러 개 있을 수 있으므로, 단순히 첫 번째 `새 채팅`을 클릭하지 않는다. MVP에서는 `채팅 검색` 노드의 화면 좌표 중심과 가장 가까운 `새 채팅` 후보를 선택한다.

좌표 기반 클릭은 MVP에 포함하지 않는다. Gemini UI 변경 등으로 selector 기반 탐지가 충분하지 않을 때를 위한 후순위 보험으로 남긴다.

### FR-042. 입력창 찾기

앱은 Gemini 입력창을 찾고 포커스해야 한다.

기존 Tasker 구현에서 사용된 입력창 ID 계열:

```text
com.google.android.googlequicksearchbox:id/assistant_robin_input_collapsed_text_half_sheet
```

탐지 전략:

1. 리소스 ID 기반 탐지
2. 입력 가능한 EditText 노드 탐지
3. 텍스트 힌트 기반 탐지

좌표 기반 입력창 클릭은 MVP에 포함하지 않는다.

### FR-043. 프롬프트 입력

앱은 다음 우선순위로 프롬프트를 입력한다.

1. 접근성 `ACTION_SET_TEXT` 직접 입력

MVP 기본 구현은 Gemini 전송 과정에서 클립보드 paste를 사용하지 않는다. 클립보드 paste fallback은 필수 기능이 아니며, `ACTION_SET_TEXT`가 특정 기기나 Gemini UI 버전에서 안정적으로 동작하지 않는 문제가 실제로 확인될 때만 MVP 이후 별도 개선 항목으로 검토한다. 좌표 클릭 후 paste는 MVP에 포함하지 않는다.

### FR-044. 보내기 버튼 클릭

앱은 Gemini의 보내기 버튼을 찾아 클릭해야 한다.

탐지 전략:

1. 텍스트 기반: `보내기`
2. contentDescription 기반: `보내기`
3. 리소스 ID 기반

보내기 버튼은 화면에 보여도 회색 비활성 상태일 수 있다. 앱은 버튼 존재만으로 성공 처리하지 않고, 클릭 가능한 상태가 될 때까지 wait/retry를 수행한 뒤 클릭한다. 클릭 후에는 입력창이 비워졌는지 확인하여 전송 완료를 추정한다. 입력창을 찾지 못해 확인할 수 없는 경우에는 성공으로 처리하지 않고 재시도한다.

좌표 기반 보내기 클릭은 MVP에 포함하지 않는다.

### FR-045. 각 프롬프트마다 새 채팅 생성

앱은 반복마다 반드시 새 채팅을 생성한 뒤 프롬프트를 전송해야 한다.

기본 반복 횟수 10회 기준 결과:

- 마커 채팅 1개
- 프롬프트 채팅 10개
- 총 11개 채팅

## 7.6 입력기 전환 및 복구

### FR-050. 현재 입력기 저장

앱은 실행 시작 시 현재 기본 입력기 ID를 저장해야 한다.

### FR-051. Null Keyboard 전환

앱은 실행 중 키보드가 Gemini UI를 가리지 않도록 지정된 입력기로 전환할 수 있어야 한다.

기본 후보:

```text
com.wparam.nullkeyboard/.NullInputMethod
```

MVP에서는 Null Keyboard가 이미 설치되어 있다고 전제한다. 설치 유도나 동봉 기능은 만들지 않는다. 활성 입력기 목록에서 Null Keyboard가 감지되지 않아도 실행을 막지 않고, 기본 후보 ID로 전환을 시도한 뒤 현재 기본 입력기를 다시 읽어 성공 여부를 판단한다.

### FR-052. 원래 입력기 복구

앱은 실행 종료, 실패, 중지 시 가능한 모든 경우에 원래 입력기로 복구를 시도해야 한다.

### FR-053. 복구 실패 안내

입력기 복구에 실패하면 앱은 다음 정보를 표시해야 한다.

- 실패 원인
- 현재 입력기 ID
- 원래 입력기 ID
- 수동 복구 안내

## 7.9 오류 처리

### FR-080. 오류 분류

앱은 오류를 다음 범주로 분류해야 한다.

| 오류 코드 | 설명 | 사용자 메시지 |
|---|---|---|
| ERR_NO_GEMINI | Gemini 앱 없음 | Gemini 앱을 찾을 수 없습니다. |
| ERR_ACCESSIBILITY_OFF | 접근성 서비스 꺼짐 | 접근성 서비스를 활성화해야 합니다. |
| ERR_NO_SECURE_SETTINGS | 권한 없음 | ADB로 WRITE_SECURE_SETTINGS 권한을 부여해야 합니다. |
| ERR_NO_PROMPT | 프롬프트 없음 | 원본 프롬프트를 입력하거나 클립보드에서 가져오세요. |
| ERR_NEW_CHAT_NOT_FOUND | 새 채팅 버튼 탐지 실패 | Gemini 새 채팅 버튼을 찾지 못했습니다. |
| ERR_INPUT_NOT_FOUND | 입력창 탐지 실패 | Gemini 입력창을 찾지 못했습니다. |
| ERR_SEND_NOT_FOUND | 보내기 버튼 탐지 실패 | Gemini 보내기 버튼을 찾지 못했습니다. |
| ERR_SEND_NOT_READY | 보내기 버튼 비활성 또는 전송 확인 실패 | Gemini 보내기 버튼이 아직 활성화되지 않았거나 전송 완료를 확인하지 못했습니다. |
| ERR_IME_RESTORE_FAILED | 입력기 복구 실패 | 입력기 복구에 실패했습니다. 수동 확인이 필요합니다. |

### FR-081. 실패 시 자동 복구

오류 발생 시 앱은 가능한 경우 다음을 수행한다.

1. 자동화 중단
2. 입력기 복구
3. 로그 저장
4. 사용자에게 실패 지점 표시

### 12.1 원칙

## 18. 오픈 이슈

MVP 개발 전 또는 개발 중 결정해야 할 항목이다.

1. Gemini 새 채팅 열기에서 sidebar를 반드시 열어야 하는가, 현재 화면 상태별 shortcut이 가능한가?
2. 각 단계별 기본 wait 시간은 몇 ms로 둘 것인가?
3. selector fallback 설정 UI를 MVP에 최소 포함할 것인가?
4. Android 최소 지원 버전은 어디까지로 할 것인가?

다음 항목은 결정 완료로 본다.

- 필요한 토큰 후보 파일이 없어도 실행을 막지 않는다.
- 좌표 fallback은 MVP에 포함하지 않고 후순위 보험으로 둔다.
- Null Keyboard는 이미 설치된 환경을 전제로 한다.
- Gemini UI 탐지는 한국어 UI 기준으로 시작한다.
- MVP 기본 프롬프트 입력 방식은 클립보드 paste가 아니라 접근성 `ACTION_SET_TEXT` 직접 입력으로 한다.
- 와일드카드 txt 파일은 실행 시작 시 1회 로드하고, 프롬프트는 각 반복 직전에 1개씩 생성한다.

## 19. 최종 MVP 정의

MVP는 다음 조건을 만족하면 성공으로 본다.

> 사용자가 앱에 원본 프롬프트를 입력하거나 클립보드에서 가져오고, 기존 `Download/wildcard/*.txt` 파일을 준비한 상태에서 실행 버튼을 누르면, 앱이 와일드카드 후보 파일을 1회 로드하고 Gemini를 열어 세션 시작 마커를 먼저 보낸 뒤, 기본 10개의 랜덤 치환 프롬프트를 각각 새 채팅에 자동 전송한다. 각 랜덤 프롬프트는 전송 직전에 1개씩 생성하며, 기본 입력 방식은 클립보드 paste가 아니라 접근성 `ACTION_SET_TEXT` 직접 입력이다. 필요한 토큰 후보 파일이 없거나 비어 있으면 해당 토큰은 원문 그대로 두고 실행을 막지 않는다. 실행 완료, 실패, 중지 시 입력기를 가능한 원래 상태로 복구하고, 성공/실패 로그를 보여준다.
