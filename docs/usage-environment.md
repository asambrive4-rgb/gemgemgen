# usage-environment.md: 사용자 실제 기기·UX 운용 환경

본 문서는 `gemgemgen` 프로젝트에서 사용자가 실제로 앱을 사용하는 **기기 구성, 화면 배치, 입력 방식, 역할 분담**을 정리한 참고 문서입니다.  
사용자가 매번 작업 요청 시 이용 환경을 다시 설명하지 않더라도, AI 에이전트가 UI/UX 기획, 화면 레이아웃 구성, 기능 제안, 원격 송수신 및 자동화 코드를 작성할 때 아래 맥락을 자연스럽게 반영할 수 있도록 작성되었습니다.

---

## 1. 전체 운영 구조 요약

* **주력 운용 방식**: **송신 기기(태블릿) + 수신 기기(스마트폰) 2대 동시 활용**
* **일반 모드 (`NORMAL`)**: 실제 주력 사용 환경이 아니며, 주로 **테스트 목적**으로 간헐적으로 사용합니다.
* **주력 자동화 대상 앱**: **`Gemini` 위주 (전체 사용량의 90% 이상)**. `ChatGPT`, `Flow`는 보조적·간헐적 용도입니다.

| 구분 | 기기 | 앱 내 모드 | 핵심 역할 |
| :--- | :--- | :--- | :--- |
| **송신 기기** | 삼성 갤럭시 탭 S7 FE | `송신` (`SENDER`) | 프롬프트 작성·송신, 각종 보조 탭/기능 관리, 큰 화면으로 Gemini 결과물 감상 |
| **수신 기기** | 삼성 갤럭시 S25 FE | `수신` (`RECEIVER`) | 요청을 받아 외부 AI 앱(주로 Gemini) 자동화를 실제로 수행하는 실행 전담 기기 |
| **단독 실행** | (테스트 시) | `일반` (`NORMAL`) | 단일 기기 기능 점검·테스트용 |

## 2. 송신 기기 환경 (`SENDER` — 갤럭시 탭 S7 FE)

### 2.1 화면 배치 및 입력 방식
* **화면 크기·비율**: 태블릿 기기이지만 GemGemGen 앱은 화면 **좌측에 세로로 길게 배치(분할/창 크기 조절)**하여 사용합니다. 따라서 **앱이 차지하는 실제 화면 폭과 비율은 스마트폰 세로 화면과 큰 차이가 없습니다.**
* **입력 방식**: 물리 키보드가 아닌 **가상 키보드(IME) 터치 입력 위주**로 사용합니다.
  * *참고*: 태블릿 환경이더라도 GemGemGen 앱 내부 UX는 좁은 세로 창 폭과 가상 키보드 점유를 전제로 하는 [`mobile-interaction-ux-guidelines.md`](file:///c:/Users/joajo/AndroidStudioProjects/gemgemgen/docs/mobile-interaction-ux-guidelines.md) 기준이 그대로 유효합니다.

### 2.2 앱 내 담당 역할 (작성·관리 중심)
자동화를 준비하고 보조하는 기능들은 **사실상 태블릿(송신 기기)에서만** 사용합니다.
* **프롬프트 작성 및 원격 송신** (`자동화` 탭)
* **단축어(상용구) 관리**: 삼성 시스템 단축어가 아닌 앱 내 **상용구(텍스트 대치, [`PromptSnippet.kt`](file:///c:/Users/joajo/AndroidStudioProjects/gemgemgen/app/src/main/java/com/example/gemgemgen/automation/domain/PromptSnippet.kt))** 기능
* **`분석 생성` 탭 / `와일드카드` 탭 / 실험(연금술) 등** 자동화 보조 기능 전반의 생성·편집·정리
* **다중 Gemini 계정 관리**: 사용량 확인 및 **수신 기기의 계정 전환 원격 제어**

### 2.3 앱 외 UX (결과물 확인)
* 송신 기기와 수신 기기는 **동일한 Google(Gemini) 계정**을 사용합니다.
* 수신 기기(스마트폰)에서 자동화로 생성된 채팅 결과는 계정을 통해 동기화되며, 사용자는 태블릿의 **큰 화면에서 Gemini 앱 목록을 직접 열어 이미지 결과물을 감상·확인**합니다.

## 3. 수신 기기 환경 (`RECEIVER` — 갤럭시 S25 FE)

* **핵심 역할**: 송신 기기가 보낸 프롬프트, 반복 횟수, 와일드카드 데이터, 계정 전환·메모리 정리 요청 등을 받아 실제 자동화를 돌리는 **실무 실행 전용 기기**입니다.
* **조작 빈도**: 자동화가 진행되는 중이나 평소 대기 상태에서 **휴대폰 화면은 거의 직접 만지지 않습니다.**
* **환경 특성**:
  * 프롬프트 편집이나 와일드카드·상용구 관리를 이 기기에서 직접 수행하는 경우는 거의 없습니다.
  * 직접 터치 조작 없이도 수신 대기·실행·상태 전달·예외 복구가 매끄럽게 이어지는 무인/최소 개입 환경이 기본입니다.

## 4. UI/UX 구성 및 코드 수정 시 참고 맥락

이 문서는 특정 모드의 기능을 막기 위한 제약이 아니라, 더 자연스러운 제안을 돕기 위한 환경 배경입니다.

1. **태블릿이지만 "좁은 세로 창 + 가상 키보드"로 가정하기**
   * 갤럭시 탭 S7 FE라고 해서 넓은 가로 2단 레이아웃이나 데스크톱·물리 키보드 중심 UX를 전제로 설계하면 오히려 사용성과 어긋날 수 있습니다.
   * 좌측 세로 창(스마트폰 폭과 유사)에서 가상 키보드로 쾌적하게 쓰고 보낼 수 있는 흐름이 실제 사용 패턴과 맞습니다.
2. **송신(작성·관리·계정 전환) vs 수신(무인 실무 실행) 흐름 구분하기**
   * 작성·편집·상용구·분석·와일드카드·계정 확인/전환 UX를 고민할 때는 "사용자가 태블릿 좌측 창을 보며 손으로 입력·조작하고, 태블릿 Gemini 앱과 병행하는 상황"을 떠올리면 자연스럽습니다.
   * 수신 측 UX나 원격 프로토콜·에러 안내를 고민할 때는 "폰 화면을 거의 만지지 않고 옆에 두는 상황"을 떠올려, 원격으로 상태를 알 수 있거나 별도 터치 개입을 최소화하는 방향이 도움이 됩니다.
3. **일반 모드(`NORMAL`) 호환 유지**
   * 주력 사용 모드는 아니지만 테스트용으로 쓰이므로, 기존 일반 모드 동작과 기본 접근성은 깨지지 않도록 유지합니다.
