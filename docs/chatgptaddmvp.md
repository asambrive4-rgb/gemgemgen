# ChatGPT 자동화 추가 MVP 계획

## 1. 문서 상태

- 상태: MVP 구현 및 실제 기기 검증 완료
- 목적: 기존 Gemini 자동화는 유지하면서 ChatGPT Android 앱에도 같은 프롬프트 반복 전송 경험을 제공한다.
- 구현 승인: 완료
- 검증 기기: Samsung Galaxy Tab S7 FE, Android 14, ChatGPT `1.2026.160`

## 2. 확정된 요구사항

| 항목 | 확정 내용 |
| --- | --- |
| 대상 앱 | Gemini, ChatGPT |
| 앱 선택 UI | `Gemini`, `ChatGPT` 두 개의 선택 버튼 |
| UI 위치 | 자동화 화면의 `프롬프트 템플릿` 제목 바로 오른쪽 |
| 기본 선택 | 저장된 선택값이 없으면 Gemini |
| 선택값 유지 | 마지막 실행 스냅샷에 대상 앱을 저장하고 앱을 다시 열 때 복원 |
| 기존 스냅샷 호환 | 과거 저장 데이터에 대상 앱 값이 없으면 Gemini로 처리 |
| 프롬프트 입력 | 기존 Gemini와 같은 접근성 `ACTION_SET_TEXT` 직접 입력 방식 |
| 세션 마커 | 기존과 동일하게 첫 채팅에 세션 시작 마커 전송 |
| ChatGPT UI 언어 | 한국어 UI 기준 |
| ChatGPT 첫 채팅 | 메뉴 열기 → 하단 `채팅` 버튼 → 입력 → 보내기 |
| ChatGPT 반복 채팅 | 전송 후 우측 상단에 나타나는 `새 채팅` → 입력 → 보내기 |
| 기존 `가져오기` 버튼 | 유지 |
| 자동화 실행 중 앱 변경 | 선택 버튼 비활성화 |

이 문서에서 “앱 선택” 또는 “대상 앱 선택”은 사용자가 말한 “모델 선택”과 같은 의미로 사용한다. ChatGPT 내부의 GPT 모델 또는 Gemini 내부의 세부 모델을 고르는 기능은 이번 MVP 범위에 포함하지 않는다.

## 3. 현재 UX와 변경 후 UX

### 현재

- 사용자는 Gemini만 대상으로 자동화를 실행할 수 있다.
- 앱 실행, 설치 확인, 버튼 탐색, 오류 문구가 모두 Gemini에 고정되어 있다.
- 첫 프롬프트는 Gemini 사이드바를 열어 새 채팅에서 세션 마커를 보낸다.
- 이후 생성된 프롬프트마다 화면에 보이는 새 채팅 버튼을 눌러 별도 채팅으로 전송한다.

### 변경 후

- 사용자는 프롬프트를 작성한 뒤 `Gemini` 또는 `ChatGPT`를 선택한다.
- 시작 버튼을 누르면 선택된 앱이 실행된다.
- 프롬프트 생성, 반복 횟수, 로그, 중지, 입력기 전환과 복구는 두 앱에서 같은 방식으로 동작한다.
- 메뉴, 새 채팅, 입력창, 보내기 버튼을 찾는 규칙만 앱별로 다르게 적용한다.
- 앱을 다시 열면 마지막 실행에 사용한 대상 앱이 다시 선택되어 있다.

## 4. 제안 UI

### 배치

```text
프롬프트 템플릿  [Gemini] [ChatGPT]                  [가져오기]
┌──────────────────────────────────────────────────────────┐
│ 프롬프트 입력                                             │
└──────────────────────────────────────────────────────────┘
```

작은 화면에서 한 줄 공간이 부족하면 제목과 앱 선택 버튼을 한 줄에 두고, `가져오기`를 같은 영역의 다음 줄 오른쪽에 배치할 수 있다. 실제 구현에서는 글자가 잘리거나 버튼이 지나치게 작아지지 않는 것을 우선한다.

### 선택 상태

- 선택된 앱 버튼은 채워진 색상 또는 강조 색상으로 표시한다.
- 선택되지 않은 앱 버튼은 외곽선 형태로 표시한다.
- 자동화 실행 중에는 두 버튼 모두 비활성화해 실행 도중 대상이 바뀌지 않게 한다.
- 접근성 사용자를 위해 각 버튼은 선택됨/선택 안 됨 상태를 제공한다.

## 5. 자동화 흐름

### 5.1 공통 준비

1. 사용자가 대상 앱, 프롬프트 템플릿, 반복 횟수를 확인한다.
2. 시작 버튼을 누른다.
3. 대상 앱을 포함한 마지막 실행 스냅샷을 저장한다.
4. 와일드카드 파일을 읽고 프롬프트 생성 계획을 준비한다.
5. 접근성 서비스와 Null Keyboard 상태를 확인한다.
6. Null Keyboard로 전환한다.
7. 선택한 대상 앱을 실행한다.

### 5.2 Gemini

기존 동작을 변경하지 않는다.

```text
Gemini 실행
→ 사이드바 열기
→ 채팅 검색 근처 새 채팅
→ 세션 마커 직접 입력
→ 보내기
→ 화면에 보이는 새 채팅
→ 생성 프롬프트 직접 입력
→ 보내기
→ 반복
```

### 5.3 ChatGPT

```text
ChatGPT 실행
→ 메뉴 열기
→ 채팅 또는 새 채팅 버튼
→ 세션 마커 직접 입력
→ 보내기
→ 화면에 보이는 새 채팅 버튼
→ 생성 프롬프트 직접 입력
→ 보내기
→ 반복 횟수만큼 새 채팅/입력/보내기 반복
```

ChatGPT의 메뉴, 채팅, 새 채팅, 입력창, 보내기 버튼은 실제 기기의 접근성 UI 구조에서 식별값을 확인했다.

### 5.4 실제 기기에서 확인된 ChatGPT 흐름

ChatGPT `1.2026.160`, 한국어 UI, 좁은 멀티윈도우 화면에서 확인한 결과:

```text
빈 채팅 화면
→ 메뉴
→ 하단 채팅 버튼
→ 입력
→ 메시지 보내기
```

메뉴 안에는 다음 두 진입점이 함께 존재한다.

- 상단 `새 채팅`
- 하단 파란색 `채팅`

하단 `채팅` 버튼을 누르면 빈 채팅 화면으로 이동하는 것을 확인했다. 사용자가 지정한 첫 흐름은 `메뉴 → 채팅`으로 구현한다.

빈 채팅 상태에서는 우측 상단 `새 채팅` 버튼이 보이지 않는다. 메시지를 전송하면 우측 상단에 contentDescription `새 채팅` 버튼이 나타나는 것을 확인했다.

```text
우측 상단 새 채팅
→ 입력
→ 메시지 보내기
→ 반복
```

우측 상단 `새 채팅`을 누르면 빈 채팅 화면으로 이동하며 버튼은 사라진다. 새 메시지를 전송하면 다시 나타난다. 따라서 ChatGPT도 Gemini와 마찬가지로 첫 세션 마커만 별도 진입 흐름을 사용하고, 이후 프롬프트는 화면에 직접 보이는 `새 채팅` 버튼을 사용한다.

### 5.5 한 회차 전송 흐름과 재시도

`프롬프트 자동화 과정.md`의 기존 “한 회차 전송 흐름과 재시도”를 Gemini와 ChatGPT 모두의 필수 공통 동작으로 유지한다. 앱별로 달라지는 부분은 새 채팅, 입력창, 보내기 버튼을 찾는 식별 규칙뿐이다.

| 흐름 | 성공하면 | 실패하면 |
| --- | --- | --- |
| 1. 새 채팅 찾기 | 클릭하고 입력창 탐색으로 이동 | 처음 3초까지 0.25초 간격, 이후 1초 간격으로 재시도 |
| 2. 입력창 찾기 | 입력창에 포커스 | 같은 재시도 규칙 적용 |
| 3. 프롬프트 입력 | 접근성 직접 입력 후 0.5초 대기 | 입력 동작이 실패하면 같은 재시도 규칙 적용 |
| 4. 입력 반영 확인 | 입력창에 전체 프롬프트가 있으면 보내기 단계로 이동 | 반영되지 않으면 같은 재시도 규칙 적용 |
| 5. 보내기 버튼 대기 | 버튼이 활성화되면 클릭 | 버튼이 없거나 비활성화되어 있으면 같은 재시도 규칙 적용 |
| 6. 전송 확인 | 클릭 후 1초 대기하고 입력창이 비었으면 성공 처리 | 프롬프트가 남아 있거나 확인할 수 없으면 같은 재시도 규칙 적용 |
| 7. 회차 종료 | 성공 수를 올리고 다음 회차로 이동 | 한 탐색 또는 확인 단계가 총 10초를 넘기면 전체 자동화를 실패 종료 |

공통 대기 기준:

| 상황 | 대기 방식 |
| --- | --- |
| 앱 UI 요소를 찾지 못함 | 단계 시작 후 처음 3초 동안 0.25초 간격으로 빠르게 재시도 |
| 3초 이후에도 찾지 못함 | 같은 단계에서 1초 간격으로 재시도 |
| 같은 단계가 10초 이상 실패 | 대상 앱과 실패 단계를 표시하고 자동화 종료 |
| 프롬프트 입력 후 확인 | 0.5초 대기 후 입력 반영 여부 확인 |
| 보내기 클릭 후 확인 | 1초 대기 후 입력창이 비었는지 확인 |

ChatGPT에서도 실제 `ui_probe` 전송 후 입력창이 비는 것을 확인했으므로 기존 전송 완료 판정 방식을 그대로 적용한다. ChatGPT 답변 완료는 기다리지 않고, 입력창이 비어 전송이 확인되면 다음 회차의 우측 상단 `새 채팅` 탐색으로 이동한다.

## 6. 책임 분리 방향

공통 자동화 정책과 앱별 Android UI 조작을 분리한다.

| 책임 | 위치/역할 |
| --- | --- |
| 대상 앱 선택값 | Android와 무관한 도메인 값 |
| 반복 횟수, 프롬프트 생성, 세션 마커 순서 | 공통 실행 유스케이스 |
| 선택 앱 실행 | 앱 실행 포트와 Android 구현 |
| 메뉴, 새 채팅, 입력창, 보내기 탐색 | Gemini/ChatGPT별 접근성 어댑터 |
| 설치 여부 확인 | 선택 앱 패키지를 기준으로 하는 환경 확인 |
| 화면 상태와 선택 이벤트 | `MainUiState`, `MainViewModel` |
| 선택 버튼 표시 | `PromptSection` |

기존 `RunGeminiAutomationUseCase`에 ChatGPT 분기를 계속 추가하면 실행 정책과 특정 앱 이름이 뒤섞인다. 구현 시 공통 실행 유스케이스로 이름과 의존성을 일반화하되, 관련 없는 와일드카드나 UI 코드는 리팩터링하지 않는다.

앱별 접근성 탐색 규칙은 한 파일에 조건문으로 합치지 않는다. ChatGPT UI 변경이 Gemini 동작에 영향을 주지 않도록 각 앱의 노드 탐색과 전송 동작을 분리한다.

## 7. 예상 변경 범위

파일명은 구현 과정에서 기존 명명 규칙에 맞춰 최소한으로 조정할 수 있다.

| 영역 | 예상 변경 |
| --- | --- |
| `MainUiState` | 선택된 대상 앱 상태 추가 |
| `MainViewModel` | 앱 선택 이벤트와 실행 요청 전달 |
| `PromptSection` | Gemini/ChatGPT 선택 버튼 추가 |
| `AutomationRunRequest` | 대상 앱 값 추가 |
| `LastRunSnapshot` | 대상 앱 저장 및 복원 |
| 스냅샷 저장소 | 대상 앱 문자열 저장, 누락 시 Gemini 기본값 |
| 자동화 유스케이스 | 앱 공통 실행 흐름으로 일반화 |
| 앱 실행기 | 선택된 패키지 실행 |
| 환경 상태 | 선택된 앱 설치 여부로 실행 가능 상태 계산 |
| 접근성 계층 | ChatGPT 전용 노드 탐색 및 전송 구현 |
| Manifest | `com.openai.chatgpt` 패키지 조회 선언 |
| 설정 화면 | 선택 앱 이름과 설치 상태 표시 |
| 문자열 | Gemini 전용 접근성 서비스 이름과 설명 일반화 검토 |
| 테스트 | 선택, 복원, 앱 실행 분기, 앱별 전송 순서 검증 |

ChatGPT 공식 Android 앱 패키지는 `com.openai.chatgpt`를 사용한다.

## 8. 화면 탐색 원칙

앱 UI는 업데이트에 따라 바뀔 수 있으므로 한 종류의 텍스트에만 의존하지 않는다.

탐색 우선순위는 실제 UI 구조를 확인한 뒤 다음 후보 중 안정적인 순서로 정한다.

1. 앱 패키지와 리소스 ID
2. contentDescription
3. 화면에 표시된 한국어 텍스트
4. 편집 가능한 입력 노드 여부
5. 클릭 가능한 부모 노드

화면 좌표를 고정해서 누르는 방식은 기기 크기와 앱 업데이트에 취약하므로 MVP 기본 방식에 포함하지 않는다.

## 9. 숨은 요구사항과 엣지케이스

### 앱 선택과 실행

- 저장된 앱 값이 손상되거나 알 수 없는 값이면 Gemini로 복구한다.
- 선택된 앱이 설치되지 않았으면 시작할 수 없고, 설정에서 해당 앱 설치 필요 상태를 보여준다.
- Gemini가 설치되어 있어도 ChatGPT가 선택된 상태라면 ChatGPT 설치 여부를 기준으로 판단한다.
- 자동화 실행 중에는 대상 앱 선택을 바꿀 수 없다.

### ChatGPT 화면 상태

- 앱 실행 시 홈, 기존 대화, 메뉴가 열린 상태 등 시작 화면이 다를 수 있다.
- 메뉴가 이미 열려 있으면 메뉴 열기 버튼을 다시 누르지 않고 다음 단계로 넘어갈 수 있어야 한다.
- 첫 화면에 새 채팅 버튼이 바로 보이는 경우에도 합의된 첫 흐름을 우선하되, 이미 열린 메뉴 상태를 정상 처리한다.
- 채팅 목록에 “새 채팅”과 비슷한 문구가 여러 개 있으면 클릭 가능한 노드와 화면 위치를 함께 사용해 잘못된 항목 선택을 줄인다.
- 메시지 전송 전 빈 채팅 화면에는 우측 상단 `새 채팅` 버튼이 없고, 전송 후에 나타난다.
- 반복용 우측 상단 `새 채팅` 버튼은 contentDescription `새 채팅`으로 찾는다.
- 음성 모드, 이미지 생성, 첨부 버튼을 보내기 버튼으로 오인하지 않아야 한다.
- 로그인, 업데이트 안내, 권한 팝업, 이용 제한 화면이 나타나면 자동으로 넘기지 않고 명확한 실패로 종료한다.

### 입력과 전송

- 기존 방식과 동일하게 실제 클립보드 붙여넣기는 사용하지 않는다.
- 입력 후 입력창에 전체 프롬프트가 반영되었는지 확인한다.
- 보내기 버튼이 활성화될 때까지 기존 재시도 정책을 사용한다.
- 보내기 클릭 후 입력창이 비었는지 확인해 전송 완료로 판단한다.
- 실제 `ui_probe` 전송에서 입력창이 빈 값으로 바뀌는 것을 확인했다.
- 빈 채팅의 입력창 안내값은 `ChatGPT에게 묻기`, 전송 후 기존 대화의 입력창 안내값은 `ChatGPT에 답장`이다. 입력창은 안내 문구보다 editable `EditText` 여부를 우선해 찾는다.
- ChatGPT가 답변을 완료할 때까지 기다리는 것은 이번 MVP 범위가 아니다. 전송 확인 후 다음 새 채팅으로 이동한다.
- 앱의 사용량 제한이나 네트워크 오류로 전송이 막히면 실패로 종료하고 원래 입력기를 복구한다.

### 종료와 복구

- 성공, 실패, 사용자 중지 모두 원래 입력기 복구를 시도한다.
- 실행 로그에는 어느 대상 앱에서 실행했는지 남기는 방안을 구현 단계에서 포함한다.
- 앱별 실패 문구를 사용해 사용자가 Gemini 문제인지 ChatGPT 문제인지 구분할 수 있게 한다.

## 10. 구현 전 필요한 실제 기기 정보

ChatGPT 버튼 탐색 규칙을 확정하기 위해 다음 화면의 접근성 노드 정보를 확인한다.

- [확인] ChatGPT 앱의 빈 채팅 화면
- [확인] 메뉴를 연 화면
- [확인] 새 채팅 화면
- [확인] 입력창에 임시 텍스트를 넣은 화면
- [확인] 보내기 버튼이 활성화된 화면
- [확인] `ui_probe` 메시지를 실제 전송한 직후의 화면
- [확인] 전송 후 우측 상단 `새 채팅`을 눌러 빈 채팅으로 이동하는 흐름

함께 기록할 정보:

- 기기 모델
- Android 버전
- ChatGPT 앱 버전
- 앱 표시 언어가 한국어인지 여부

가능하면 ADB로 연결한 실제 기기에서 `uiautomator dump`와 스크린샷을 함께 확보한다. 비밀번호, 이메일, 채팅 제목이나 대화 내용 같은 개인정보가 포함되면 문서나 테스트 데이터에 저장하지 않는다.

### 현재 확인된 테스트 기기

| 항목 | 확인값 |
| --- | --- |
| 기기 | Samsung Galaxy Tab S7 FE (`SM-T733`) |
| Android | Android 14, API 34 |
| ChatGPT 앱 | `1.2026.160` (`versionCode 2616021`) |
| 시스템 언어 | 한국어 (`ko-KR`) |
| ADB 연결 | 연결 확인 |

따라서 사용자가 별도로 기기와 앱 버전을 전달할 필요는 없다. 메뉴, 새 채팅, 입력창, 보내기 버튼의 UI 구조와 전송 후 흐름도 확인했다.

### 확인된 ChatGPT 접근성 식별값

| 동작 | 확인된 식별값 | 클릭 방식 |
| --- | --- | --- |
| 메뉴 열기 | contentDescription `메뉴` | 해당 노드 또는 클릭 가능한 부모 |
| 첫 채팅 열기 | 표시 텍스트 `채팅` | 텍스트 노드의 클릭 가능한 부모 |
| 반복 새 채팅 | contentDescription `새 채팅` | 전송 후 우측 상단에 나타난 해당 노드 또는 클릭 가능한 부모 |
| 입력창 찾기 | `android.widget.EditText`, editable `true` | 편집 가능한 노드 우선 |
| 빈 채팅 입력창 보조값 | contentDescription `ChatGPT에게 묻기` | 입력창 후보 검증에 사용 |
| 전송 후 입력창 보조값 | contentDescription `ChatGPT에 답장` | 입력창 후보 검증에 사용 |
| 보내기 | contentDescription `메시지 보내기` | 해당 노드의 클릭 가능한 부모 |

이 버전에서는 위 요소들의 Android resource ID가 노출되지 않았다. 따라서 패키지 `com.openai.chatgpt`, 접근성 설명값, 표시 텍스트, 편집 가능 여부, 클릭 가능한 부모를 조합해 탐색한다.

## 11. 테스트 계획

### 자동 테스트

- 앱 선택 기본값이 Gemini인지 확인
- Gemini와 ChatGPT 선택 이벤트가 상태에 반영되는지 확인
- 실행 요청에 선택 앱이 포함되는지 확인
- 마지막 스냅샷에서 선택 앱이 복원되는지 확인
- 과거 스냅샷에 앱 값이 없을 때 Gemini로 복원되는지 확인
- Gemini 선택 시 Gemini 패키지를 실행하는지 확인
- ChatGPT 선택 시 `com.openai.chatgpt`를 실행하는지 확인
- 선택 앱의 설치 상태에 따라 실행 가능 여부가 달라지는지 확인
- 세션 마커와 반복 프롬프트가 모두 선택된 앱 게이트웨이로 전달되는지 확인
- ChatGPT 첫 프롬프트와 반복 프롬프트가 서로 다른 새 채팅 방식을 사용하는지 확인
- Gemini와 ChatGPT 모두 각 탐색 단계에서 3초까지 0.25초, 이후 1초 간격으로 재시도하는지 확인
- 입력 후 0.5초, 보내기 후 1초의 확인 대기가 유지되는지 확인
- 한 탐색 또는 확인 단계가 10초를 넘기면 실패 종료되는지 확인
- 실행 중 앱 선택 버튼이 비활성화되는 UI 상태 확인
- 기존 Gemini 자동화 테스트가 계속 통과하는지 확인

### 실제 기기 테스트

1. Gemini 선택 후 기존 자동화가 이전과 동일하게 동작한다.
2. ChatGPT 선택 후 앱이 정상 실행된다.
3. 메뉴를 열고 하단 `채팅` 버튼으로 진입한 첫 채팅에 세션 마커가 전송된다.
4. 각 생성 프롬프트가 별도 새 채팅에 전송된다.
5. 자동화 도중 중지하면 추가 전송이 멈추고 입력기가 복구된다.
6. ChatGPT가 설치되지 않은 상태에서 정확한 안내가 나온다.
7. 앱을 종료하고 다시 열어도 마지막 대상 앱 선택이 복원된다.
8. 기존 저장값만 있는 업그레이드 상황에서는 Gemini가 선택된다.

## 12. 완료 기준

- 프롬프트 템플릿 영역에서 Gemini와 ChatGPT를 선택할 수 있다.
- 마지막으로 실행한 대상 앱이 앱 재실행 후 복원된다.
- Gemini 기존 자동화 동작에 회귀가 없다.
- ChatGPT에서 세션 마커와 설정한 횟수의 프롬프트가 각각 새 채팅으로 전송된다.
- 두 대상 앱 모두 기존 한 회차 전송 순서와 재시도·대기 기준을 동일하게 사용한다.
- ChatGPT 버튼 탐색 실패 시 대상과 단계가 드러나는 오류가 표시된다.
- 성공, 실패, 중지 후 원래 입력기가 복구된다.
- 관련 단위 테스트와 빌드가 통과한다.
- 실제 Android 기기에서 두 앱의 기본 성공 흐름을 각각 확인한다.

## 13. MVP 제외 범위

- ChatGPT 내부 GPT 모델 선택
- Gemini 내부 세부 모델 선택
- 영어 등 다국어 UI 탐색
- 실제 클립보드 붙여넣기
- 화면 좌표 고정 클릭
- ChatGPT 응답 내용 수집
- 응답 완료 대기
- 로그인이나 권한 팝업 자동 처리
- 앱 UI 탐색 규칙을 사용자가 직접 편집하는 기능

## 14. 구현 및 검증 결과

- 좁은 멀티윈도우 화면에서 `프롬프트 템플릿`, Gemini/ChatGPT 선택 버튼, `가져오기` 버튼이 겹치지 않고 한 줄에 표시됨
- 마지막 실행 스냅샷의 대상 앱을 ChatGPT로 저장하고 앱 재실행 후 복원되는 흐름 확인
- 기존 스냅샷에 대상 앱 값이 없을 때 Gemini로 복원되는 단위 테스트 통과
- ChatGPT에서 접근성 `ACTION_SET_TEXT` 직접 입력 성공
- 세션 마커를 첫 채팅에 전송한 뒤 우측 상단 `새 채팅`으로 반복 프롬프트를 별도 채팅에 전송 성공
- 실제 테스트에서 `ui_automation_probe` 1회 전송 성공
- ChatGPT 최근 채팅 목록에서 세션 마커 채팅과 테스트 프롬프트 채팅이 별도로 생성된 것을 확인
- 실행 로그에서 `대상 앱: ChatGPT`, 반복 `1/1`, 성공 `1`, 실패 `0`, 세션 마커 성공 확인
- 전송 후 입력창이 비는 기존 완료 판정 방식이 ChatGPT에서도 동작함을 확인
- 단위 테스트와 디버그 APK 빌드 통과
