# LightMemo 기능/UX 이식용 MVP 문서

## 1. 문서 목적

이 문서는 현재 LightMemo 앱의 코드 구조를 그대로 가져오기 위한 문서가 아니다.

목표는 현재 앱에서 사용자에게 보이는 기능, UX 흐름, UI 구성을 분석해 다른 앱에 기능으로 이식할 때 필요한 MVP 범위를 정리하는 것이다.

## 2. 앱 한 줄 요약

LightMemo는 사용자가 선택한 로컬 폴더 안의 텍스트 파일을 빠르게 열고, 클립보드 내용을 붙여넣고, 저장하고, 복사할 수 있는 단순 메모 편집 앱이다.

## 3. 핵심 사용자 가치

- 여러 메모를 앱 내부 DB가 아니라 사용자가 고른 폴더의 `.txt` 파일로 관리한다.
- 파일 목록을 탭처럼 보여주어 메모 간 전환이 빠르다.
- 클립보드 내용을 기존 메모에 덮어쓰기 또는 아래에 이어붙이기 할 수 있다.
- 메모 내용을 다시 클립보드로 복사할 수 있다.
- 저장하지 않은 변경사항이 있을 때 사용자가 실수로 잃어버리지 않도록 확인한다.

## 4. MVP 범위

| 구분           | MVP 포함 여부 | 설명                           |
| ------------ | --------: | ---------------------------- |
| 저장 폴더 선택     |        필수 | 사용자가 직접 저장 폴더를 선택한다.         |
| 텍스트 파일 목록 표시 |        필수 | 선택한 폴더 안의 파일을 탭/버튼 형태로 표시한다. |
| 파일 열기        |        필수 | 파일을 선택하면 내용을 편집기에 표시한다.      |
| 새 파일 생성      |        필수 | 이름을 입력해 새 `.txt` 파일을 만든다.    |
| 파일 삭제        |        필수 | 현재 선택한 파일을 삭제한다.             |
| 메모 편집        |        필수 | 큰 텍스트 입력 영역에서 내용을 수정한다.      |
| 저장           |        필수 | 현재 편집 내용을 파일에 저장한다.          |
| 클립보드 덮어쓰기    |        필수 | 클립보드 텍스트로 현재 메모 전체를 교체한다.    |
| 클립보드 아래 붙여넣기 |        필수 | 현재 메모 아래에 클립보드 텍스트를 추가한다.    |
| 메모 복사        |        필수 | 현재 메모 전체를 클립보드에 복사한다.        |
| 간단한 되돌리기     |        권장 | 붙여넣기/덮어쓰기 직전 상태로 되돌린다.       |
| 검색           |        제외 | 현재 앱에 없음. MVP에 포함하지 않는다.     |
| 폴더/파일 동기화    |        제외 | 클라우드 동기화 기능은 현재 앱에 없음.       |
| 서식 있는 메모     |        제외 | 일반 텍스트만 다룬다.                 |

## 5. 주요 화면 구성

현재 앱은 사실상 하나의 화면으로 구성된다.

| 영역         | 역할                          | UX 포인트                                    |
| ---------- | --------------------------- | ----------------------------------------- |
| 파일 탭 영역    | 선택한 폴더의 파일 목록 표시            | 작은 버튼을 격자 형태로 배치한다. 선택된 파일은 색과 테두리로 강조한다. |
| 파일 관리 버튼   | 새 파일 생성, 현재 파일 삭제           | 아이콘 버튼으로 작게 배치한다.                         |
| 현재 파일 상태   | 선택된 파일명과 저장 여부 표시           | 저장되지 않은 변경이 있으면 파일명 뒤에 `*`를 표시한다.         |
| 저장 폴더 영역   | 현재 저장 폴더 표시, 폴더 선택/변경       | 폴더가 없거나 접근 불가하면 경고 문구를 보여준다.              |
| 빠른 작업 버튼 줄 | 붙여넣기, 아래 붙여넣기, 저장, 복사, 되돌리기 | 가장 자주 쓰는 작업을 편집기 위에 크게 배치한다.              |
| 텍스트 편집기    | 메모 내용 작성/수정                 | 화면 남은 높이를 대부분 차지한다. 고정폭 글꼴을 사용한다.         |

## 6. 기본 사용자 흐름

### 6.1 첫 실행

1. 사용자가 앱을 연다.
2. 저장 폴더가 선택되어 있지 않으면 파일 목록과 편집 기능은 비활성화된다.
3. 앱은 "폴더를 선택하라"는 안내를 보여준다.
4. 사용자가 `Select Folder` 버튼을 누른다.
5. 시스템 폴더 선택 화면에서 폴더를 고른다.
6. 앱이 폴더 접근 권한을 저장한다.
7. 폴더 안의 파일 목록을 불러온다.
8. 첫 번째 파일이 있으면 자동으로 연다.

### 6.2 메모 파일 전환

1. 사용자가 상단 파일 탭을 누른다.
2. 현재 메모에 저장하지 않은 변경이 없으면 즉시 전환한다.
3. 저장하지 않은 변경이 있으면 확인 창을 띄운다.
4. 사용자는 `Save`, `Discard`, `Cancel` 중 하나를 선택한다.

| 선택 | 동작 |
|---|---|
| Save | 현재 파일을 저장한 뒤 새 파일을 연다. |
| Discard | 변경사항을 버리고 새 파일을 연다. |
| Cancel | 전환하지 않고 현재 화면에 머문다. |

### 6.3 새 파일 생성

1. 사용자가 새 파일 버튼을 누른다.
2. 저장하지 않은 변경이 있으면 먼저 확인 창을 띄운다.
3. 파일명 입력 창을 보여준다.
4. 사용자가 파일명을 입력한다.
5. 앱은 `.txt` 확장자가 없으면 자동으로 붙인다.
6. 같은 이름의 파일이 있으면 생성하지 않고 안내한다.
7. 생성에 성공하면 새 파일을 바로 연다.

### 6.4 클립보드 기반 입력

| 버튼 | 동작 |
|---|---|
| Paste | 클립보드 텍스트로 현재 메모 전체를 교체한다. |
| Paste Below | 현재 메모 아래에 클립보드 텍스트를 추가한다. 기존 내용 끝에 줄바꿈이 없으면 줄바꿈을 한 번 넣는다. |
| Copy | 현재 메모 전체를 클립보드로 복사한다. |
| Undo | Paste 또는 Paste Below 직전 상태로 되돌린다. |

주의할 점:

- 클립보드가 비어 있으면 작업하지 않고 안내 메시지를 보여준다.
- 복사할 내용이 비어 있으면 작업하지 않고 안내 메시지를 보여준다.
- 현재 앱의 되돌리기는 일반 텍스트 편집 전체에 대한 완전한 undo가 아니라, 앱 버튼으로 변경하기 전 상태를 최대 5개까지 저장하는 방식이다.

### 6.5 저장

1. 사용자가 편집기에 텍스트를 입력한다.
2. 저장된 내용과 현재 내용이 다르면 파일명 뒤에 `*`가 붙는다.
3. 사용자가 `Save` 버튼을 누른다.
4. 현재 파일에 텍스트를 저장한다.
5. 저장 성공 시 `*` 표시를 제거하고 안내 메시지를 보여준다.

## 7. UI 스타일 가이드

| 요소 | 현재 앱의 느낌 | 이식 시 유지할 포인트 |
|---|---|---|
| 전체 분위기 | 밝고 부드러운 메모장 | 복잡한 도구보다 빠른 입력 도구처럼 느껴져야 한다. |
| 색상 | 연한 보라, 파랑, 초록, 노랑 계열 | 주요 버튼마다 기능별 색을 약하게 구분한다. |
| 버튼 | 둥근 Material 버튼 | Paste/Save는 크게, Copy/Undo는 아이콘 중심으로 작게 둔다. |
| 파일 탭 | 작은 격자 버튼 | 파일이 많아도 위에서 빠르게 고를 수 있어야 한다. |
| 선택 상태 | 배경색과 진한 테두리 | 현재 열린 파일이 명확해야 한다. |
| 편집기 | 큰 입력 영역, 고정폭 글꼴 | 메모 내용이 화면의 중심이어야 한다. |

## 8. 상태와 예외 처리

| 상황 | 필요한 UX |
|---|---|
| 저장 폴더 미선택 | 폴더 선택 안내를 보여주고 편집/저장/삭제 버튼을 비활성화한다. |
| 저장 폴더 접근 불가 | 다시 폴더를 선택하라는 경고를 보여준다. |
| 파일 없음 | 편집기는 비우고 `No file selected` 상태를 보여준다. 새 파일 생성은 가능해야 한다. |
| 저장 전 이동/폴더 변경/새 파일 생성 | 저장, 버리기, 취소 중 선택하게 한다. |
| 파일 열기 실패 | 실패 안내를 보여준다. |
| 저장 실패 | 실패 안내를 보여준다. |
| 삭제 실패 | 실패 안내를 보여준다. |
| 빈 파일명 | 생성하지 않고 파일명을 입력하라고 안내한다. |
| 중복 파일명 | 생성하지 않고 이미 존재한다고 안내한다. |

## 9. 데이터 모델

MVP에서 필요한 데이터는 단순하다.

| 데이터 | 설명 |
|---|---|
| 선택된 저장 폴더 | 사용자가 고른 폴더 URI 또는 경로 |
| 메모 파일 목록 | 저장 폴더 안의 파일명과 파일 위치 |
| 현재 파일 | 현재 선택된 파일명과 파일 위치 |
| 저장된 원본 내용 | 현재 파일을 열거나 저장했을 때의 내용 |
| 편집 중인 내용 | 사용자가 현재 입력 중인 내용 |
| 변경 여부 | 저장된 원본 내용과 편집 중인 내용이 다른지 여부 |
| 되돌리기 기록 | 클립보드 작업 전의 텍스트 스냅샷 |

## 10. 이식 시 권장 구현 순서

1. 단일 화면 레이아웃을 만든다.
   - 확인 방법: 파일 탭, 폴더 영역, 작업 버튼, 편집기가 한 화면에 보인다.

2. 저장 폴더 선택과 권한 저장을 구현한다.
   - 확인 방법: 앱을 다시 열어도 이전 폴더를 기억한다.

3. 폴더 안의 텍스트 파일 목록을 표시한다.
   - 확인 방법: 파일명이 탭으로 표시되고 선택한 파일이 강조된다.

4. 파일 열기/저장/새 파일 생성을 구현한다.
   - 확인 방법: 새 파일을 만들고 내용을 저장한 뒤 다시 열 수 있다.

5. 클립보드 Paste, Paste Below, Copy를 구현한다.
   - 확인 방법: 클립보드 텍스트가 의도한 방식으로 반영된다.

6. 저장하지 않은 변경사항 보호를 구현한다.
   - 확인 방법: 파일 전환이나 폴더 변경 전에 저장 확인 창이 뜬다.

7. 삭제와 간단한 Undo를 구현한다.
   - 확인 방법: 현재 파일 삭제 후 다음 파일이 열리거나 선택 없음 상태가 된다. Paste 전 상태로 되돌릴 수 있다.

## 11. MVP 완료 기준

- 사용자가 폴더를 선택할 수 있다.
- 폴더 안의 텍스트 파일 목록을 볼 수 있다.
- 파일을 선택해 내용을 열 수 있다.
- 새 파일을 만들 수 있다.
- 내용을 편집하고 저장할 수 있다.
- 클립보드 텍스트를 덮어쓰기 또는 아래 붙여넣기 할 수 있다.
- 현재 메모 내용을 클립보드로 복사할 수 있다.
- 저장하지 않은 변경사항이 있을 때 전환 전에 확인한다.
- 저장 폴더 접근 불가, 빈 클립보드, 빈 파일명, 중복 파일명 같은 기본 예외를 사용자에게 안내한다.

## 12. 현재 앱에서 관찰된 주의사항

- 현재 앱은 기능이 대부분 한 Activity에 모여 있다. 이식할 때 코드를 그대로 복사하기보다는 화면, 저장소, 클립보드 처리, 변경사항 보호 로직을 역할별로 나누는 편이 좋다.
- 현재 문자열 리소스에는 편집기 힌트 문자열이 깨져 보이는 부분이 있다. 이식 시 `Type here...` 같은 정상 문구로 다시 정의해야 한다.
- 삭제 동작에는 별도 확인 창이 없다. 다른 앱에 넣을 때는 실수 방지를 위해 삭제 확인 창을 추가하는 것을 권장한다.
- 파일 목록은 모든 파일을 보여준다. MVP에서는 `.txt` 파일만 보여줄지, 모든 일반 파일을 보여줄지 정책을 먼저 정하는 것이 좋다.
- 현재 Undo는 앱 버튼으로 발생한 변경만 대상으로 한다. 사용자가 키보드로 직접 입력한 모든 변경까지 되돌리는 기능으로 오해되지 않게 해야 한다.
