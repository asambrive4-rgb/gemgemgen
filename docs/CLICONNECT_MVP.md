# MVP-0 작업 지시서: gemgemgen 테스트 탭에서 Antigravity CLI 연결 검증

## 1. 목표

`gemgemgen` Android 앱에 새로운 `테스트` 탭을 추가한다.

이 탭의 목적은 실제 기능 구현이 아니라, Android 앱에서 로컬 PC의 Antigravity CLI까지 요청을 보내고 답변을 받아올 수 있는지 검증하는 것이다.

이번 MVP는 다음 왕복 흐름이 동작하는지만 확인한다.

- Android 앱의 `테스트` 탭에서 요청 입력
    
- 로컬 PC의 Bridge Server로 요청 전송
    
- Bridge Server가 Antigravity CLI에 요청 전달
    
- Antigravity CLI 답변 수신
    
- Android 앱의 `테스트` 탭에 답변 표시
    

---

## 2. 이번 MVP의 핵심 범위

이번 단계에서는 오직 연결 검증만 구현한다.

|구분|내용|
|---|---|
|추가 탭|`테스트`|
|입력|사용자가 테스트 프롬프트 입력|
|요청 대상|로컬 PC의 Bridge Server|
|실제 AI 호출|Antigravity CLI|
|출력|CLI 답변 문자열 표시|
|목적|Android 앱 ↔ Antigravity CLI 왕복 연결 확인|

---

## 3. 반드시 지켜야 할 조건

- 반드시 Antigravity CLI를 사용한다.
    
- Gemini API를 사용하지 않는다.
    
- Google AI Studio API를 사용하지 않는다.
    
- Vertex AI를 사용하지 않는다.
    
- API 키 기반 호출을 추가하지 않는다.
    
- Android 앱이 Antigravity CLI를 직접 실행하지 않는다.
    
- Android 앱은 로컬 Bridge Server에 요청만 보낸다.
    
- Bridge Server가 Antigravity CLI 실행을 담당한다.
    
- 기능은 집에서 로컬로 사용하는 것을 전제로 한다.
    
- 외부 공개 서버나 클라우드 배포는 고려하지 않는다.
    

---

- 프롬프트 50개 생성 기능

- 히스토리 저장

- 실제 UI 디자인 완성
    
- 정식 기능 탭 구성
    
- 배포용 설정
    

이번 단계에서는 기능을 만들지 않는다.  
오직 연결이 되는지만 확인한다.

---

## 5. `테스트` 탭 요구사항

`테스트` 탭에는 최소한 다음 요소가 있어야 한다.

|요소|역할|
|---|---|
|Bridge Server 주소 입력|로컬 PC Bridge Server 주소 설정|
|인증 토큰 입력|로컬 연결 보호용 토큰 입력|
|테스트 프롬프트 입력|Antigravity CLI에 보낼 간단한 문장 입력|
|요청 버튼|Bridge Server로 요청 전송|
|응답 표시 영역|Antigravity CLI의 답변 표시|
|오류 표시 영역|연결 실패 또는 실행 실패 메시지 표시|

UI는 임시 형태여도 된다.  
다만 사용자가 앱 안에서 직접 테스트할 수 있어야 한다.

---

## 6. 테스트 프롬프트 예시

기본 테스트 프롬프트는 다음 의미의 문장으로 둔다.

> 한국어로 짧게 답해줘. 연결 테스트 성공이라고 말해줘.

사용자는 이 문장을 수정해서 다른 요청도 테스트할 수 있어야 한다.

---

## 7. 기대 응답

정상 연결 시 Android 앱의 `테스트` 탭에 Antigravity CLI의 답변이 표시되어야 한다.

예상되는 응답의 의미는 다음과 같다.

> 연결 테스트 성공입니다.

응답 문구가 정확히 같을 필요는 없다.  
중요한 것은 Android 앱에서 보낸 요청이 Antigravity CLI까지 전달되고, 그 답변이 다시 Android 앱에 표시되는 것이다.

---

## 8. 오류 처리 요구사항

다음 상황에서 앱이 크래시 나면 안 된다.

- Bridge Server가 실행 중이 아님
    
- Bridge Server 주소가 잘못됨
    
- 인증 토큰이 잘못됨
    
- Antigravity CLI 실행 실패
    
- Antigravity CLI 응답 지연
    
- 네트워크 연결 실패
    
- 빈 프롬프트 전송
    
- 응답 형식이 예상과 다름
    

오류 발생 시 `테스트` 탭에 사람이 이해할 수 있는 한국어 오류 메시지를 표시한다.

---

## 9. Bridge Server 역할

Bridge Server는 Android 앱과 Antigravity CLI 사이의 중계 역할만 한다.

Bridge Server의 책임은 다음으로 제한한다.

- Android 앱의 요청 수신
    
- 요청에 포함된 테스트 프롬프트 확인
    
- Antigravity CLI에 프롬프트 전달
    
- Antigravity CLI 답변 수신
    
- Android 앱에 답변 반환
    
- 실패 시 오류 반환
    

이번 MVP에서 Bridge Server는 분석 로직이나 카테고리 로직을 포함하지 않는다.

---

## 10. Android 앱 역할

Android 앱은 `테스트` 탭에서 다음 역할만 수행한다.

- Bridge Server 주소 저장 또는 입력
    
- 테스트 프롬프트 입력
    
- 요청 전송
    
- 응답 표시
    
- 오류 표시
    

이번 MVP에서 Android 앱은 프롬프트 분석, 카테고리 판단, 결과 가공을 하지 않는다.

---

## 11. 보안 조건

이 기능은 로컬 개인 사용을 전제로 한다.

- Bridge Server는 외부 인터넷에 공개하지 않는다.
    
- Google 계정 정보는 Android 앱에 저장하지 않는다.
    
- Google 계정 쿠키나 세션을 다루지 않는다.
    
- API 키를 앱에 저장하지 않는다.
    
- 요청 보호를 위해 로컬 인증 토큰을 사용한다.
    
- 전체 요청/응답 내용을 불필요하게 로그에 남기지 않는다.
    

---

## 12. MVP 성공 기준

다음 조건을 모두 만족하면 MVP-0은 성공으로 본다.

- 앱에 `테스트` 탭이 추가되어 있다.
    
- `테스트` 탭에서 Bridge Server 주소를 입력할 수 있다.
    
- `테스트` 탭에서 인증 토큰을 입력할 수 있다.
    
- `테스트` 탭에서 테스트 프롬프트를 입력할 수 있다.
    
- 요청 버튼을 누르면 로컬 Bridge Server로 요청이 전송된다.
    
- Bridge Server가 Antigravity CLI에 요청을 전달한다.
    
- Antigravity CLI의 답변이 Android 앱에 표시된다.
    
- Bridge Server가 꺼져 있어도 앱이 크래시 나지 않는다.
    
- CLI 실행 실패 시 앱이 크래시 나지 않는다.
    
- Gemini API 키 없이 동작한다.
    

---

## 13. Codex 작업 지침

Codex는 이번 단계에서 기능을 확장하지 않는다.

우선순위는 다음 하나다.

> `테스트` 탭에서 Antigravity CLI까지 요청과 답변이 왕복되는지 검증한다.

기존 앱 구조를 크게 바꾸지 않는다.  
새 기능의 정식 UI나 분석 기능은 다음 단계로 미룬다.  
이번 작업은 이후 `분석 생성`, `카테고리`, `50개 생성` 기능을 붙이기 위한 연결 기반을 만드는 단계다.
